# 摘要自检：对照优秀论文后的问题清单

> 本文档记录一次对照式自检：拿当前摘要与机器人领域代表性论文的摘要骨架对比，
> 找出结构、动机与措辞上的差距。正文见 [abstract_draft.md](./abstract_draft.md)，
> 内容大纲见 [abstract_outline.md](./abstract_outline.md)。

## 1. 对照样本与摘要骨架

| 论文 | 出处 | 摘要骨架 | 可借鉴 |
| --- | --- | --- | --- |
| NeuPAN | TRO 2025 | 挑战（杂障未知环境中的非完整运动规划）→ 方法定位（real-time、map-free、环境不变）→ 两个关键创新 → 核心机制（PAN）→ 三平台多环境评估 → 收尾承诺 | 先给方法定位再给机制；机制服务于定位 |
| DARE | ICRA 2025 | 任务（自主探索）→ 传统方法局限 → 学习方法潜力 → 方法一句话（diffusion + 一次性推理 + attention + GT 示范）→ 能力陈述（依据部分 belief 推理未知区域）→ 结果定位（与 SOTA 持平 + 泛化） | 每个组件在一句话内给出“为什么”；明确一次性推理的部署价值 |
| SPARTA | RSS 2025 | 关键开放挑战（通过性依赖朝向）→ 朴素编码的代价（数据 + 重复推理）→ 洞见（利用几何结构）→ 机制（1-球面上的平滑解析函数、Fourier 基）→ 数字结果（91% vs 73%）+ 硬件 | 与我们的边界样条最像：把“利用几何结构”写成核心洞见 |
| MPD | IJRR 2025 | 优化规划依赖初始解 → 学习轨迹分布作先验 → diffusion + 代价引导 → B 样条低维参数化及其理由 → 实验范围 | 表示选择必须给理由；“为什么样条”要明确写出来 |
| YOPO | RA-L | 单阶段规划器、无显式地图、运动原语覆盖搜索空间、单次前向预测偏移与评分 | 单次前向的部署价值一句话点出 |
| CAP | arXiv 2025 | 挑战（不平地形 + 倾覆）→ 需求（防倾覆 + 有效导航）→ 稳定性金字塔 → 可通行朝向 → 约束 → 图优化求解 → sim + real 验证 | 稳定性约束来自真实物理定义，先定义后使用 |
| Wheeled Mobility on Vertically Challenging Terrain | RA-L | 直接否定常见假设（2D free/obstacle 划分）→ 学习 vehicle-terrain 前向动力学 → 不翻车不卡住 → 两台物理样机 | 用一个具体假设的失效建立问题 |
| Learning Robust Autonomous Navigation for Wheeled-Legged Robots | Science Robotics 2024 | 潜力（物流）→ 完整系统（自适应运动控制 + 局部导航 + 大范围路径规划）→ 系统意义 | 系统级摘要以能力和意义收束 |

## 2. 当前摘要的问题清单

1. **开头是“通用义务句”，没有“难在哪”。**
   “Global path planning must output a route that satisfies ... ” 对任何规划器都成立，
   读者得不到本问题的张力。CAP 和 SPARTA 都以一个具体挑战开头（倾覆风险、朝向相关
   通过性）。修改方向：把“部分观测 + 边界约束同时存在”作为张力点。

2. **缺少“现有方法为什么不行”，方法因此显得是自由组装。**
   摘要没有一句话说明 baseline 会在哪一步失败：本文规划器的固定尺寸输入可能填不满时（mask
   语义）、端点作为条件需要学习时。DARE 与 MPD 都会先讲传统方法局限。修改方向：
   明确两个困难，让每个方法组件逐一回应。

3. **组件平铺、缺核心洞见。**
   现状按“样条 → 法向 + mask → 两阶段 → 部署”顺序平铺，没有一句统领的 insight。
   SPARTA 的 “exploit geometric structure”、BridgeFlow 的 “task-centric
   canonicalization” 都是先给洞见。我们的洞见应写为：已知的任务几何属于表示层，
   不交给网络学习；观测覆盖的不确定性属于输入层，用 mask 显式表达。

4. **“Path MeanFlow planner”出现，但没有说“为什么是生成式”。**
   DARE 写明 “explicitly generate an exploration path through one-time inference”。
   我们至少应点出：生成式模型把示范中的长程路线结构变成可采样的部署分布，且一次
   前向即可输出。

5. **三个代价（forbidden / stability / curvature）无前导、术语堆叠。**
   它们出现在一个括注里，读者不知道为什么是这三项。要么在问题段先引出（倾覆风险、
   禁入区域），要么在摘要中合并为 terrain-feasibility costs，细节留给 Method。

6. **部署句写成了系统管道，真正的承诺没有说。**
   “one latent sample and one forward pass ... passed to a downstream local
   planner” 是工程接口；真正的卖点是边界由构造保证、部署不需要完整地图、不需要
   在线优化。这些才是值得写进摘要的承诺。

7. **缺少收束定位。**
   结果占位符之前没有一句“我们展示了什么”。强摘要至少给一个能力定位（如
   real-time、环境不变、与 SOTA 持平并泛化）。定位词可以现在就定下来，数字等
   结果冻结后再填。

8. **中文版偏说明文。**
   “使每类信息各司其职”是抽象概括；应改成“任务结构由表示层承担、观测不确定性由
   输入层表达”这类与机制一一对应的说法。

## 3. 建议的五段式骨架

1. 具体挑战：崎岖地形下，端点约束与地形可行性必须同时成立。
2. 两个困难：固定窗口在建图过程中可能填不满（掩码语义）；端点作为学习条件
   （边界违例）。
3. 核心洞见 + 方法一句话：以“边界精确表示 + 两阶段训练（示范先验 → 完整地图
   特权适应）”一句话概括方法，不展开机制细节。
4. 机制：只保留一句话级要点——端点由构造固定、掩码条件化生成、完整地形代价反传
   至部署时使用的单步输出；不在大纲中逐条展开。
5. 部署承诺 + 证据：一次前向、无在线优化、只依赖当前部分观测；[实验设置] 与
   [主要定量结果]。

## 5. 第二轮措辞修正

第一轮重写后仍存在若干生硬表达，本轮统一改为论文常用语：

| 原表达 | 问题 | 现表达 |
| --- | --- | --- |
| endpoints hold by construction | “hold” 与 endpoint 不搭配 | endpoint constraints are satisfied exactly |
| forbidden clearance | 省略过度、语义残缺 | clearance（放在 terrain-feasibility costs 括注内） |
| arbitrary coverage | 含义空泛 | varying coverage |
| obstacles here | 口语化 | 直接以两个困难句承接 |
| 禁入区域净距 | 测绘行业词，不通用 | 禁入区域距离 |
| 观测覆盖形态 | 自造搭配 | 不同程度的地图覆盖 |
| 端点条件由构造满足 | 直译痕迹 | 端点约束因此被精确满足 |
| 稳定性余度 | 与主流术语不一致 | 稳定裕度 |
| 将 A、B、C 结合起来 | 三个不同层（表示/生成/训练）被硬性并列，“结合”是空动词，读作模块清单 | 改为三个平行分句：任务几何定义生成空间，路线生成以当前观测为条件，完整地形在训练期提供可行性监督 |
| 掩码条件化的路线生成 | 自造标签，把输入通道抬成方法名 | 概览句只写“以当前观测为条件”，法向与掩码在机制句展开 |
| two-stage planner | 易被误读为串联双网络 | 经两阶段训练的规划器（training is staged） |
| 反传至部署时使用的单步输出 | 方向错误：代价由单步输出计算后再反传 | 由部署时使用的单步输出计算代价并反传至网络 |
| reference path | 与 Stage 1 示范轨迹混淆 | global path |
| 困难句中写“掩码区分……” | 解法与困难混为一谈 | 困难句只描述填不满，掩码出现在方法句（区分已观测/未观测/禁入栅格） |
| demonstration paths | 可能被理解为示教轨迹数据集 | expert routes |
| 继续训练同一生成器 | 冗余 | 删除，训练句以“并反向传播”收束 |
| 英文写 Stage 1/Stage 2 | 过于直白 | 用 pre-training / post-training 表达两阶段训练 |
| 以部署时使用的单步输出 | 冗余 | 删除，只写“计算可微特权代价并反向传播” |
| 可微可行性代价 | 术语不一致 | 可微特权代价 |
| 部署时仅需一次网络前向 | 与 MeanFlow 固有属性重复 | 删除，不在摘要中单独说明 |
| 掩码化地形观测区分……作为路线生成条件 | 主语缠绕、读起来别扭 | 路线生成以地形观测和掩码为条件，掩码区分已观测栅格与未观测或禁入栅格 |
| 上下文约束的样条表示让网络只生成…… | “让”字句式别扭 | 端点位姿由上下文约束的样条表示解析确定，网络只需生成内部路线几何 |
| 结果句写成“提升地形可行性+保持端点满足” | 未落在方法真正的预期结论上 | 结论聚焦特权后训练的有效性（硬可行性提升），端点约束表述为表示构造保证且在覆盖变化下成立 |

第三轮修正后仍有遗漏，分析如下：

- “窗口内已观测的区域随建图进度变化”：变化对象仍停留在“区域”这一模糊概念，且
  与实现（mask 标记的栅格集合）脱节。改为“窗口内被真实地形观测填充的范围随
  建图进度变化”，并保留“本文规划器的输入尺寸固定”作对照；该句与“只覆盖其中的一部分”
  存在信息冗余，最终压缩为“输入窗口尺寸固定，其中被真实地形观测填充的范围随
  建图进度变化”。
- 用户随后指出该压缩句仍不准确：问题不是“填充范围随建图进度变化”，而是扫描
  地图往往填不满固定尺寸窗口，因此需要掩码把未观测或禁入区域与已观测区域区分。
  最终表述为“在渐进式建图过程中，扫描地形可能尚未填满规划器固定尺寸的输入
  窗口，未观测或禁入的部分需要由掩码与已观测区域区分”；“往往填不满”的频率
  表述随后被用户纠正为“建图过程中会出现填不满的情况”。
- “一次隐变量采样与网络前向”：随机源是标准高斯 source，并非学习到的隐变量，
  “隐变量”一词会误导读者；部署承诺只保留“一次网络前向”。
- “learning-based global planning ... from a fixed-size terrain window” 将本文规划器的
  输入接口误写成学习型规划的普遍属性；任务句改为一般的崎岖地形规划要求，并在
  “In our setting” 后再引入固定尺寸窗口。
