# 方法大纲（会议后重构）

本文大纲先说明每一部分要回答什么问题，再列出需要展开的技术内容。完整公式和实现细节保留在 `method_draft.md`，这里不按代码模块堆叠。

## Overview

### 要讲什么

Path MeanFlow 面向崎岖地形上的全局路径生成。规划器根据当前可用的地形信息，为给定的起点和终点生成一条参考路径。路径不仅要到达目标，还应避开当前不能进入的区域、降低车辆倾覆风险，并避免超过车辆转向能力的急弯。

方法由两项核心设计构成：

1. **Boundary-aligned trajectory representation** 将已经确定的起终点位置和朝向写入路径表示，网络只负责生成两端之间的路线形状。
2. **Two-stage learning** 先从专家路径学习长距离绕行结构，再利用训练阶段可用的完整地形信息适配物理可行性，并协调不同物理目标之间可能冲突的梯度。

显式 mask、条件生成网络和一次前向部署是连接两项核心设计的支撑链路，不作为独立的网络架构贡献。

### Overview 图怎么画

从左到右画出：当前地形观测与 mask、起终点任务、边界对齐路径空间、Path MeanFlow 生成器和解析样条路径。训练部分在生成器上方画出“专家路线学习 -> PMTA”的两个阶段；完整地形只以虚线进入 PMTA，并标注 `training only`。部署分支只保留带掩码的当前观测、一个 source、一次前向和一条输出路径。

## 1. 问题表述与信息边界

### 要回答的问题

规划器在部署时看到了什么，需要输出什么，哪些信息只在训练时可用？

### 内容

- 输入包括当前地形观测、表示当前可规划区域的 mask，以及起终点位姿。
- 输出是交给下游局部规划器跟踪的二维全局参考路径。
- mask 标记已经观测且允许车辆中心进入的区域；未知区域和已知禁入区域都不能作为当前路径的可靠支撑。
- 完整地形只用于训练阶段的物理监督和离线评价，不作为部署输入。
- 无人机只作为上游观测来源，不把论文写成无人机建图到车辆控制的端到端系统。

### 怎么讲

先用车辆要完成的规划任务建立直觉，再定义固定规划窗口、可变规划支撑和训练/部署信息边界。只保留定义后续公式确实需要的符号。

## 2. Boundary-aligned trajectory representation

### 要回答的问题

为什么不让网络直接预测整条路径的所有坐标？

### 内容

- 直接生成所有坐标时，起终点位置和朝向只能通过损失函数交给网络学习，不能保证每次生成都精确满足。
- 将路径变换到由起终点定义的规范坐标系，消除平移、旋转和尺度造成的非必要变化。
- 使用 clamped cubic B-spline，并以四个解析边界控制点固定起终点位置和一阶方向。
- 网络仅预测内部控制点对应的自由坐标；解析解码器再将其还原为物理路径。
- 标准高斯 source 只作用于内部路线形状，因此所有生成样本共享相同的任务边界。

### 本节要建立的结论

端点位置和方向由表示构造保证；地形可行性不由这一表示保证，而由后续学习和实验评价。

## 3. Planning-support-conditioned generator

### 要回答的问题

网络如何根据当前已知地形决定两端之间应该走哪条路线？

### 内容

- 地形法向提供已观测区域中的几何信息，mask 防止网络把未知区域的填充值当成真实地形。
- 起终点任务、当前生成状态和 MeanFlow 时间共同构成路径生成条件。
- 地形编码器产生 map tokens，路径自由坐标产生 path tokens；二者通过条件调制和交叉注意进行交互。
- 网络最终输出内部路径自由坐标，再由边界对齐样条解码。
- CAP 的地形回归和倾覆稳定性模型作为继承的物理接口，不作为本文重新提出的模块。

### 怎么讲

先解释各输入分别提供什么信息，再用一段话概括网络数据流。层数、宽度、注意力头数等实现参数放到 Experimental Setup，不把网络画成主要创新。

## 4. Two-stage learning and deployment

### 4.1 Expert route-prior learning（ERPL）

#### 要回答的问题

生成器如何学会长距离绕行，而不是只在局部物理代价上移动路径？

#### 内容

- 将专家路径编码到边界对齐自由坐标中。
- Path MeanFlow 从标准高斯 source 学习专家路径的条件分布。
- 部署 endpoint 监督与 MeanFlow 训练目标共同约束一次前向输出。
- 该阶段学习路线结构，但不声称已经满足完整地形上的全部物理要求。

### 4.2 Privileged multi-objective terrain adaptation（PMTA）

#### 要回答的问题

如何把训练阶段能够计算的物理风险吸收到一次前向生成器中？

#### 内容

- 从 ERPL checkpoint 初始化，在与部署一致的一次前向输出上计算物理目标。
- 三项目标分别描述路径越出当前规划区域、车辆倾覆风险和曲率违反。
- 完整地形只参与倾覆稳定性目标；生成器本身始终只接收部署时可见的输入。
- 三项目标保持独立，使用 MGDA 在当前训练点求取局部协调梯度并更新同一生成器。
- MGDA 是已有优化工具；本文贡献是特权三目标训练及其与单步路径生成器的结合。
- 不声称普遍的共同下降、Pareto 最优、训练收敛或硬安全保证。

### 4.3 Deployment

- 每次重新规划采样一个标准高斯 source。
- 生成器执行一次 endpoint 前向，解析样条解码得到一条路径。
- 部署不读取完整地形，不计算训练期稳定性场，不附加在线轨迹优化，也不进行多路径择优。
- 输出路径交给下游局部规划器；本文只评价全局参考路径生成，不把局部跟踪结果归因于生成器的解析保证。
